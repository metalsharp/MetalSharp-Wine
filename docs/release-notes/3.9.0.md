## Minecraft Bedrock starts, fullscreen mode changes that work, and more frame rate limits

WineMetalGL 3.9.0 fixes a freeze in Minecraft Bedrock's OpenGL startup and emulates display mode changes, so fullscreen games at a lower resolution cover the screen. It also adds more frame rate limits to WineMetalGL Settings and fixes the install into CrossOver's arm64 bottles.

### 32 color bits for RGBA8 pixel formats

- **The bug:** `wglChoosePixelFormatARB` found no format for `WGL_COLOR_BITS_ARB` 32, because RGBA8 formats reported 24 color bits.
- **Minecraft Bedrock** asks for exactly that when it probes OpenGL at startup (RGBA8, depth 24, stencil 8, double-buffered). Finding no format, it retried forever and froze before its menu.
- **The fix:** RGBA8 formats now report 32 color bits, as Windows drivers do. A request for 24 still matches.

### Emulated display mode changes ([#86](https://github.com/metalsharp/WineMetalGL/issues/86))

- **On by default, without a preset.** A program sees the real display and all of its modes. When it changes the mode, it sees the new one while the real mode stays. Its fullscreen window covers the screen, and its frames are scaled to it. Nothing is scaled until it changes the mode.
- **`WINEMETALGL_EMULATE_MODES=0`** (or `off`) turns it off.
- **Why:** a real mode change through Wine's macOS driver sometimes deadlocked, leaving a blank window. When it didn't, the mode didn't always take, so the game drew in one corner of the screen. With the emulation, EDuke32's fullscreen 1280x720 came up covering the screen in 11 of 11 runs.
- **The mode list now holds 1024 modes.** The old 64 held only part of a real display's sizes, depths and rates, which made EDuke32 pick 960x540 for its 1280x720.

### Frame rate limits of 30 to 60 fps ([#76](https://github.com/metalsharp/WineMetalGL/issues/76))

- **The Frame Rate Limit card** in WineMetalGL Settings now offers Off, 30, 35, 40, 45, 50, 55 and 60 fps, in two rows of four.
- **40 fps** divides a 120 Hz display's refresh rate evenly, which 45 doesn't.

### CrossOver arm64 bottles ([#75](https://github.com/metalsharp/WineMetalGL/issues/75))

- **The bug:** `install-crossover.sh` treated a bottle as 32-bit unless its `cxbottle.conf` said `"WineArch" = "win64"`. A bottle of CrossOver's arm64 Wine says `arm64` there, so it got the i386 `opengl32.dll` and `winemetalgl.dll`. 64-bit programs then failed to load `opengl32.dll` (`c000007b`, for example Steam's `vgui2_s.dll`).
- **The fix:** the bottle's `system32` `ntdll.dll` now decides. Without one, only `"WineArch" = "win32"` makes a bottle 32-bit.
