## Frame rate limit, NotProton games, and fixes for old games and wined3d

WineMetalGL 3.8.0 adds a frame rate limit and NotProton support to WineMetalGL Settings. It also fixes a startup crash in Quake III engine games, a fence-wait bug that broke wined3d, and a white screen in Mewgenics.

### Frame rate limit ([#76](https://github.com/metalsharp/WineMetalGL/issues/76))

- **`WINEMETALGL_MAX_FRAME_RATE=<fps>`** limits how often `SwapBuffers` returns, with or without vsync. Any value works, for example `30`, `40` or `59.94`.
- **Like DXMT's `preferredMaxFrameRate`, it slows the game itself, not just the display.** Older DX7–9 and OpenGL games often tie their physics to the frame rate and have no limit except vsync. That runs them at 120 fps on a 120 Hz display. The limit also saves battery.
- **WineMetalGL Settings** has a new **Frame Rate Limit** card with Off, 60, 45 and 30 fps. A value set by hand in the settings file stays until you pick another.

### NotProton games in WineMetalGL Settings ([#73](https://github.com/metalsharp/WineMetalGL/issues/73))

- **What's listed:** WineMetalGL Settings lists the Steam games [NotProton](https://github.com/NotProtonNot/NotProton) has set up, in every Steam library. Each is named with the NotProton runner it uses.
- **Install** puts WineMetalGL into that runner and the game's prefix. The game then has the same on/off switch as a CrossOver bottle.
- **How it's set up:** WineMetalGL runs Wine the way NotProton does, with the runner's own Wine loader and wineserver. `install-wine-module.sh` gains `WINEMETALGL_WINE_LOADER` for this.
- **When it's removed:** NotProton replacing a runner, or rebuilding a game's prefix, removes WineMetalGL from it. The game then shows **Install** again.

### Fixes

- **Quake III engine games no longer crash at startup** ([#75](https://github.com/metalsharp/WineMetalGL/issues/75)): for example Star Wars Jedi Knight: Jedi Academy.
  - **Cause:** these games print `GL_EXTENSIONS` through a 4096-byte buffer, and WineMetalGL's string was 4988 bytes.
  - **Fix:** programs that ask for OpenGL 1.x or 2.x now get the string under 3900 bytes, oldest extensions first.
  - Nothing is turned off: `glGetStringi` still lists every extension, and programs that ask for 3.x or later get the whole string.
  - `WINEMETALGL_EXTENSIONS_LENGTH=<n>` changes the limit, and `0` turns it off.
- **Fence waits with "wait forever" timeouts wait again.** wined3d waits for its fences with a timeout of `~0 >> 1` ns. Adding that to the clock overflowed, so every such wait timed out at once. wined3d logged `glClientWaitSync returned 0x911b` and "Failed to wait for command fence".
- **Mewgenics no longer shows a white screen** ([#77](https://github.com/metalsharp/WineMetalGL/issues/77), by [@Gre4kas](https://github.com/Gre4kas)). MSL keywords used as struct type names, such as a struct named `vertex`, are now renamed like other names. Before, Metal rejected the shaders that used them.
