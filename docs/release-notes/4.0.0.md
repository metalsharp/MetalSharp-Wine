## Mari's viewport, per-game settings, any frame rate limit, and SteamVR finds OpenGL

WineMetalGL 4.0.0 compiles shaders that Foundry Mari's viewport needs, adds per-game settings through a `winemetalgl.conf` beside a game's `.exe`, and adds 100 fps, 120 fps and custom frame rate limits to WineMetalGL Settings. SteamVR also finds OpenGL now.

### Foundry Mari's viewport shaders ([#88](https://github.com/metalsharp/WineMetalGL/issues/88))

- **Sampler arrays indexed by a variable below GLSL 4.00.** Mari's `#version 330` shaders index `sampler2D tiles[N]` with a variable, which the shader compiler refused ("variable indexing sampler array"). Desktop drivers accept it, and so does Metal, so it now compiles with a warning. GLSL ES keeps its rule.
- **Locals named after Metal functions.** A GLSL local such as `vec3 dfdx = dFdx(F);` became `float3 dfdx = dfdx(F);` in the Metal shader, which Metal rejects. Names of Metal-only functions (`dfdx`, `dfdy`, `rsqrt`, `select`...) are now renamed in the Metal shader.
- **Not fixed yet:** the crash Mari reported while saving the pipeline cache (`PipelineArchive::save`). It hasn't been reproduced, so #88 stays open for it.

### A game's own settings, and any frame rate limit ([#76](https://github.com/metalsharp/WineMetalGL/issues/76))

- **`winemetalgl.conf` beside a game's `.exe`** holds settings for that game only, as `dxvk.conf` and `dxmt.conf` do for DXVK and DXMT. It uses the same `WINEMETALGL_*=value` lines as `settings.conf`, wins over it, and loses to the environment. For example, `WINEMETALGL_MAX_FRAME_RATE=100` for a game whose physics break past 105 fps, while other games keep the limit set in the app.
- **The Frame Rate Limit card** in WineMetalGL Settings adds 100 and 120 fps, in two rows of five, and a **Custom** field for any other limit (105, 59.94...).
- The limiter itself is unchanged.

### SteamVR finds OpenGL

- **The bug:** SteamVR showed "Please install OpenGL before using SteamVR" and exited. It checks for OpenGL by reading `opengl32.dll`'s version resource, and WineMetalGL's `opengl32.dll` had none.
- **The fix:** `opengl32.dll` now has a version resource like Windows' ("OpenGL Client DLL"), in the x86_64, i386 and ARM64X builds. Its exports are unchanged.
