## WineMetalGL in arm64 Wine

WineMetalGL 3.7.0 runs inside a native arm64 Wine: CrossOver 27's arm64 bottles and MetalSharp's Wine with FEX ([#13](https://github.com/metalsharp/WineMetalGL/issues/13)). It works for native ARM64 programs, x86_64 ones and 32-bit ones, on the arm64 core, with no Rosetta. Until now the Wine module was built for x86_64 Wine only, so in CrossOver 27 the forwarding `opengl32.dll` loaded but `winemetalgl.dll` didn't ("Failed to load module winemetalgl.dll", c0000135).

### The arm64 Wine module

- **`winemetalgl-3.7.0-arm64.tar.gz`** is a new package next to the x86_64 one, from `scripts/stage-release-arm64.sh`:
  - `winemetalgl.dll` and the `opengl32.dll` forwarder are **ARM64X**, so one DLL serves native ARM64 programs and x86_64 ones, which an arm64 Wine runs as ARM64EC.
  - An i386 build covers 32-bit programs through WoW64.
  - `winemetalgl.so` and the core are arm64.
- **Fixes for the ARM64 half of an ARM64X DLL:**
  - The exception reporter reads an x64 `CONTEXT`, so it's now built for x86_64 and ARM64EC only, not for the native ARM64 half.
  - An arm64 Wine runs x86 code through its own emulator, not Rosetta, so the x87 sidecar hook is x86_64-host only. FEX's reduced-precision x87 mode is the counterpart.
- **Tested in MetalSharp Wine 2.0** (Wine 11.20 with FEX): OpenGL 4.6 WineMetalGL Core Profile in native ARM64 and x86_64 programs, with rendering checked by reading a pixel back.

### The install scripts pick the right package

- **`install-wine-module.sh`** works out whether the Wine is an x86_64 Wine or an arm64 one:
  - from the unix side it has (`lib/wine/x86_64-unix` or `aarch64-unix`);
  - for a Wine with both, from the prefix's own `system32`;
  - `WINEMETALGL_ARCH` overrides the detection.
- **`install-crossover.sh`** reads the bottle's own `system32/ntdll.dll` (ARM64 in a CrossOver 27 arm64 bottle, x86_64 in an x86_64 one), so it works with or without CrossOver installed. An arm64 bottle gets:
  - the arm64 module in `~/Library/Application Support/WineMetalGL/lib/wine/{aarch64-windows,i386-windows,aarch64-unix}`;
  - a `[Wine] DllPath` default built on `aarch64-windows`;
  - the ARM64X `opengl32.dll` and `winemetalgl.dll` in `system32`, with the i386 ones in `syswow64`.
- **Either package installs into either kind of Wine:** when a package isn't for the Wine it's given, the script downloads the matching one from the release (checked against `SHA256SUMS.txt`). x86_64 Wine and bottles install exactly as before.
- **MetalSharp Wine:**
  - A folder of MetalSharp Wine gets its bundled WineMetalGL updated in place, with no prefix setup needed, since it's already the default OpenGL there.
  - The signed `MetalSharp-Wine.app` is left alone; it already uses WineMetalGL.
