# MetalSharp Wine x86_64

MetalSharp Wine's x86_64 build is MetalSharp's regular runtime: an x86_64 Wine that runs under Rosetta 2, shipped as one Developer ID-signed app, `MetalSharp-Wine-x86_64.app`. The arm64 build runs x86 code with FEX instead. The two share prefixes, the same graphics lanes, the same `.metalsharp/launch.env` model and the same game fixes. MetalSharp's FEX | x86_64 toggle switches between them.

Releases of this repository carry it next to the arm64 build. Every x86_64 asset has `x86_64` in its name:

| Asset | Contents |
|---|---|
| `MetalSharp-Wine-<version>-x86_64.zip` | `MetalSharp-Wine-x86_64.app`: Wine, every graphics lane, D3DMetal and the media libraries, signed with the hardened runtime |

### How Wine picks a lane

Wine picks a lane by itself from `GRAPHICS_BACKEND`, which MetalSharp writes to a game's `.metalsharp/launch.env`:

| `GRAPHICS_BACKEND` | Lane |
|---|---|
| `dxmt` | Mullion: Direct3D 12, 11 and 10 to Metal (64-bit), and Direct3D 11 and 10 (32-bit) |
| `vkd3d` (or `dxvk`) | VKD3D / DXVK: VKD3D-Proton's Direct3D 12 with the full DXVK beside it (Direct3D 11 to 8, 64-bit and 32-bit), on MoltenVK |
| `d3dmetal` | D3DMetal: Apple's Direct3D 12 and 11, x86_64 only |
| `wine` | Wine's own Direct3D, on WineMetalGL |

Each lane's DLLs come from the app. Nothing is staged into game folders.

MetalSharp reads the macOS version when each game starts. Below macOS 27, D3DMetal is Game Porting Toolkit 3.0's, Mullion is held to Metal 3.2 shaders (`mullion.shaderMetalVersion = 320`) and the VKD3D lane's Direct3D 9 to shader model 3 (`d3d9.shaderModel = 3`). macOS 27 and later run Game Porting Toolkit 4.0 beta 3's D3DMetal and Mullion's own Metal version.

Games that come with DLSS are shown an NVIDIA GeForce RTX 4080 on every lane and run DLSS on MetalFX:
- **Mullion and VKD3D / DXVK:** through each lane's own NGX core.
- **D3DMetal:** through Apple's `nvngx-on-metalfx`, Super Resolution only.
- **Frame Generation:** needs hardware-accelerated GPU scheduling, which Wine reports.

## Source

`source/wine-x86_64` is Wine 11.17 as ported by [WineForge](https://github.com/Alien4042x/WineForge) (Radim Veselý; its `main` up to `a05564cf`), with MetalSharp's 59 commits on top. The same commits are in `patches/wine-x86_64/` as git patches against `a05564cf`.

The first of them, "MetalSharp runtime as shipped", is the source of the Wine in MetalSharp's `bundles` release. The rest are MetalSharp Wine's fixes, carried over to this Wine, and the x86_64 work:
- the lanes loaded from `launch.env`;
- WineMetalGL as the default OpenGL;
- DLSS on every lane;
- Frame Generation;
- running in prefixes shared with the arm64 build;
- per-folder tracing (`.metalsharp/trace`);
- `HideWineExports`.

## Building

The app is assembled from the `bundles` release's Wine runtime, with the modules MetalSharp's commits change rebuilt from `src/wine-x86_64` and laid over it, plus the lanes.

```bash
zsh scripts/fetch-sources.sh x86_64
```

Then, in order:

1. **Wine's modules** (kernelbase, ntdll, win32u, winemac.drv, wined3d, winevulkan, wow64 and wineserver): `X86_WINE_BUILD=<tree> zsh scripts/build-wine-x86_64.sh`.
   - `<tree>` is an x86_64 build tree configured from `src/wine-x86_64`, with `--build=x86_64-apple-darwin --host=x86_64-apple-darwin --enable-archs=i386,x86_64` and `CC='clang -arch x86_64 -mmacosx-version-min=15.0'`.
   - Its PE side needs Homebrew's `mingw-w64`.
2. **Media:** `zsh scripts/build-deps-x86_64.sh` builds GStreamer and FFmpeg into `deps/prefix-x86_64`.
3. **Mullion:** `X86_WINE_BUILD=<tree> zsh scripts/build-mullion-x86_64.sh` builds into `install-x86_64/lib/dxmt`.
4. **WineMetalGL:** `zsh scripts/build-winemetalgl-x86_64.sh` builds into `install-x86_64/winemetalgl`.
5. **The app:** `scripts/package-x86_64.sh <output dir>`, with the inputs its header lists. These are the `bundles` release, the VKD3D-Proton-MacOS and DXVK-MacOS releases, MoltenVK, D3DMetal, the outputs above, `VERSION` and `SIGN_IDENTITY`.
   - A full build takes about 90 seconds.
   - For a release, set `TIMESTAMP=1`, since notarization needs secure timestamps. Zip the app with `ditto -c -k --keepParent` as `MetalSharp-Wine-<version>-x86_64.zip` (about 1.3 GB).
   - The Notarize workflow takes `arch: x86_64`.

**Not yet scripted:** configuring a fresh build tree. Its dependencies (gnutls, freetype, SDL2, Samba's netapi, the EGL headers) were taken from the `bundles` runtime and Homebrew by hand. `build-deps-x86_64.sh` covers the media libraries only.

## Limits

- **Rosetta 2 required:** x86_64 code runs under Rosetta. 32-bit programs run on Wine's WoW64.
- **32-bit games on VKD3D / DXVK start without the Metal HUD.** Apple's HUD throws an exception in a 32-bit program's MoltenVK device.
- **D3DMetal has no Ray Reconstruction:** Apple's NGX reports no denoiser on this OS.
